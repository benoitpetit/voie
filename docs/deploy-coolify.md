# Deploy voie on Coolify

The public endpoint is served by the Cloudflare Worker on `voie.devbyben.fr`.
This Coolify application is the authenticated origin behind that Worker. The
local API origin must have its own HTTPS hostname, reachable from Cloudflare,
and must not resolve back through `voie.devbyben.fr`.

## Build and run

Create a Coolify application from the `core` repository and use its root
`Dockerfile`. The image listens on port `8080`; configure Coolify to expose
that container port over HTTPS on a hostname reserved for this origin. Do not
point the Worker at `voie.devbyben.fr`, because that would send the request
back through the Worker.

`deploy.devbyben.fr` is the Coolify server/control hostname. Use the HTTPS
hostname assigned to this application as Worker variable `VOIE_ORIGIN_URL`,
for example the application's own `https://...` URL shown by Coolify.

Mount a persistent volume at `/data`. voie stores local conversation data in
`/data/conversations.db`.

## Required secret

Set `API_TOKEN` in the Coolify application environment to a high-entropy secret
generated for this origin. Do not commit or print the value. The Go service
binds to `0.0.0.0:8080` in the container and refuses to start on a non-loopback
host when `API_TOKEN` is empty.

Set `REQUIRE_CONVERSATION_SCOPE=true` in the Coolify environment as well. Deploy
the updated Core image with this setting before deploying the Worker that sends
project scopes. During the interval, requests without a verified scope receive
`401`; after the Worker update, active project keys receive their isolated
conversation namespace. `/health` remains available to the authenticated
container health check.

Set the exact same secret as the Cloudflare Worker secret `VOIE_ORIGIN_TOKEN`.
The Worker replaces each project's API key with this origin token before
forwarding the request. Project keys are not valid against the Go application.

The project keys are generated by the separate local web-repository tool
(`npm run tokens:admin`) and checked at the Cloudflare edge against D1. Do not
configure those project keys as `API_TOKEN` in this application; only the
private shared origin value belongs here.

## Smoke check

From a trusted machine, verify that the origin rejects a request with no bearer
and accepts the health check with the configured origin token:

```sh
curl -sS -o /dev/null -w '%{http_code}\n' https://<coolify-app-host>/health
curl -sS -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer $VOIE_ORIGIN_TOKEN" \
  https://<coolify-app-host>/health
```

Expected status codes are `401` and `200`. Keep the token in a secret manager or
shell environment; do not paste it into the URL or command history.

The Docker image has a built-in `HEALTHCHECK` that runs `voie healthcheck` every
30 seconds. It calls the local `/health` route, uses `API_TOKEN` when configured,
and reports the container unhealthy when the route does not return `200`.

## Browser-backed provider

The image includes Debian's Chromium package for the DuckAI provider. Other
providers do not require a browser. Keep the mounted `/data` volume when
recreating the container so locally stored conversations survive deployments.
